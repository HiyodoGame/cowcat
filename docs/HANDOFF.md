## 1. 本批完成

实机截图暴露旧侧栏无边界、空面板机械均分和 41×23 象限猫过大的问题。本批按用户确认的计划完成：

| 类别 | 内容 | 结果 |
|---|---|---|
| 原生分组 | 活动与信息面板使用细边框和原生中性标题 | 不再用品牌绿底代替边界，空态区块全部保留 |
| 内容高度 | 左侧面板自然增高，空间不足时从最高面板压缩到最小 3 行 | 空态待办/子代理/后台为 4/3/3 行；长列表保留 `另有 N 项` |
| 点阵猫 | 64×40 逻辑点，2×4 Braille 子点，32×10 终端单元 | 水平居中、底部对齐；稀疏灰点背景，无象限实块、文字或彩色 |
| 六种眼神 | idle 眨眼和灰阶呼吸、thinking 视线、tools 半阖、approval 睁大、success 弯眼、failed 垂眼 | 保留状态优先级和 reduced-motion；idle 呼吸已有可见像素变化 |
| 信息排版 | 短字段标签与值同行，长路径按路径段换行 | `CowCat 变更` 改为 `文件变更`，空态辅助文案简化 |
| 空会话与输入 | 完全无内容时显示原生“开始新会话”面板；提示补 Shift+Enter | 有消息、思考、工具或流式内容时不显示欢迎卡；英文提示在 64 列完整可见 |

偶数网格的严格对称与单鼻点通过**同一终端单元内两个居中逻辑鼻点**同时满足。协议、内核事件、端口、模型、工具行为、响应式断点和依赖均未改变。

## 4. 独立审查与 deferred minors

独立 reviewer 未发现 Critical；唯一 Important 是首个 reasoning delta 尚未 reveal 时误显示欢迎卡，已新增 `reasoningShown=0` 回归用例，先 RED 后 GREEN，最终 TUI 246/246。

本批记录的 deferred minors：Braille 同格优先级可能隐藏眼睛高光；窄终端欢迎提示仍可能裁切；`06-frontend.md` 一处旧“无真实终端证据”措辞待后续清理。它们不作为本批已修事项。

## 5. 未验证 / 风险

- conhost 的灰色比 Tabby 暗；不同终端的 Braille 字形、灰阶、闪烁与长时间使用仍需人眼复核，不能由 headless 结果替代。
- 160×32 和 160×40 的尺寸与坐标由真实渲染测试覆盖；真实窗口只做人眼布局检查，不声称逐像素跨终端一致。
- 本批未调用付费模型端点，不改变模型行为；远端 CI、提交、PR 与合并需后续按仓库流程完成。
