# TUI 固定侧栏与灰阶点阵猫设计

> 视觉方向已由用户确认：固定分区布局于 2026-10-28 通过；简化点阵猫样式与六种表情于 2026-10-29 通过。
> 实现基线应为 `origin/main` 的最新提交，而不是当前本地 `main` 上已被远端压缩合入的重复提交。

## 1. 意图

当前宽终端的左右栏只在有数据时挂载面板，整列又被拉伸到终端高度，因此空会话会出现大片没有结构、也没有解释的空白。与此同时，现有猫咪是彩色像素画，和用户希望的简洁、黑白灰、设备感点阵形象不一致。

本次改动要解决两件事：

1. 让宽终端的活动区、信息区始终有稳定的空间结构，空数据也有明确空态。
2. 用原创的灰阶点阵设备猫替换现有像素猫，并主要通过眼睛表达状态。

## 2. 目标、非目标与反目标

### 目标

- 宽终端按用户参考图渲染固定区块，空数据不再退化为无结构空白。
- 猫咪区域没有文字，点阵背景铺满整个区域；猫咪由 82×46 逻辑点构成。
- 只使用黑、白、灰及其中间灰阶；样式简单、左右对称，保留一个小鼻点。
- 六种状态主要通过眼睛形状和视线表达；`COWCAT_ANIMATIONS=off` 时保持静态。
- 不降低中间会话区的可读性，不改变现有输入、审批、滚动和命令行为。

### 非目标

- 不修改协议、内核事件、端口、模型或工具行为。
- 不引入 React/Solid、图片资源、终端图片协议或新依赖。
- 不重做中间会话区、模态对话框或窄终端单栏布局。
- 不复制 WorkBuddy 的资产、绿色、比例或标志轮廓。

### 反目标

- 空面板不允许没有标题或空态说明。
- 不允许为了显示猫咪把中间正文压到不可读宽度。
- 不允许持续随机闪烁、整只猫反复跳动，或用动画代替真实状态。
- 不恢复黑色方块眼、彩色鼻子、额外奶斑、嘴巴或右侧突出的耳尖。

## 3. 已确认的布局

### 宽终端

- 左栏自上而下固定为：**待办、子代理、后台任务、猫咪**。
- 右栏自上而下固定为：**信息、Git 与变更文件**。
- 中栏保持现有会话流、审批/计划 dock、状态条和 composer。
- 猫咪固定在左栏底部；其余左侧活动面板分配剩余空间，右下变更区弹性增长。

### 空态与溢出

所有区块始终渲染，即使没有任何数据：

- 待办：`暂无待办`，辅助说明 `任务出现后会列在这里`。
- 子代理：`暂无运行中的子代理`。
- 后台任务：`暂无后台任务`。
- Git 与变更文件：`暂无 CowCat 变更`，辅助说明 Write/Edit 成功后会出现文件与 diffstat。
- 信息区保留模型、上下文、目录等字段；未知值显示 `未记录` / `等待首次用量`，不整块省略。

面板内容受可视高度约束。数据过多时显示当前可见行和 `另有 N 项`，不允许把后续区块或猫咪顶出屏幕。左栏是摘要，不新增一套与 dock 冲突的交互或状态。

### 响应式

82×46 逻辑点按每终端字符 2×2 子点渲染，因此猫咪实际占 **41 列 × 23 行**。为保留至少约 80 列的中栏阅读空间，以下阈值是本次设计的工程取舍，不是用户逐项指定：

- 宽度 ≥160 且高度 ≥32：完整三栏。
- 104–159：只显示右侧信息栏，左侧活动信息回到现有 dock。
- <104、高度 <32 或 `COWCAT_SIDEBAR=off`：使用现有单栏/dock 回退。
- 猫咪逻辑网格不得因宽度缩小而变形；空间不足时回退，而不是裁掉眼睛或耳朵。

## 4. 已确认的点阵猫

### 形状

- 82×46 逻辑点阵，左右镜像对称。
- 圆角方形灰色头部，配外撇双耳；右耳最外侧与头部边界收齐，不多出尖点。
- 中央是独立的白色圆角面罩。
- 面罩中央偏下只有一个小灰鼻点；没有嘴巴和额外奶斑。
- 不使用文字标签；背景点阵铺满整个猫咪区域，猫咪位于视觉中心。

### 灰阶

背景、外轮廓、面罩、虹膜、瞳孔和鼻点使用可区分的黑白色与多级灰色。语义 token 可以复用现有 `cat*` 命名，但不再使用品牌绿或粉色。外轮廓在 `#1B1B22` 背景上必须可见，眼睛在白色面罩上必须可读。

### 眼睛

默认是竖条眼：浅灰外圈 + 中灰内芯 + 少量浅灰高光。浅灰外圈用于避免深色眼点被点阵间隙吞没；不得改成纯黑眼块。

| 状态 | 眼睛表情 | 辅助运动 |
|---|---|---|
| idle | 正常竖条眼，周期性眨眼 | 很轻的呼吸亮度；平时安静 |
| thinking | 瞳孔按左 / 中 / 右移动 | 低对角度斜向波，不能盖过视线 |
| tools | 半阖眼，竖条高度缩短 | 低对比列扫描 |
| approval | 竖条眼明显变长、睁大 | 头部保持静止 |
| success | 双眼变成向上的弯眼 | 一次短脉冲后静止 |
| failed | 双眼下垂或倾斜 | 不做持续抖动 |

状态优先级沿用现有实现：待审批 > 工具/后台工作 > 思考 > 短暂成功/失败反馈 > idle。动画计时仍由 `activityDelay` / 主渲染节拍驱动；隐藏、销毁和 `COWCAT_ANIMATIONS=off` 时不得继续排程。关闭动画后保留当前状态的静态眼形，状态文本由现有状态栏承担，不在猫咪区域补文字。

## 5. 渲染与代码边界

- `app/rails.ts` 始终生成完整左/右栏结构及空态，不再用 `null` 省略空面板。
- `Screen` 负责固定猫咪底部位置、其余面板的高度分配和响应式回退，不让空内容决定布局是否存在。
- 猫咪继续由 `components/cowcat-art.ts` 产出固定尺寸的纯数据帧；`mascotState(view, now)` 的回合推导保持独立。
- 82×46 光栅通过 41×23 终端单元的 2×2 子点绘制。象限/半块只作为 Sprite 内容，不得变成手拼边框或 UI 装饰字符；布局仍由原生 Scene/Box 组件承担。
- 每个字符单元可以使用前景/背景两种灰阶，因此不需要终端图片协议。文本宽度差异由真实渲染测试覆盖，不能假设所有终端的象限字形都完全一致。
- 保留 keyed 更新、可见区域挂载和现有 `Screen` 公共输入/命令接口。

## 6. 验证要求

- 结构测试：所有空面板存在且有空态；有数据时行数有界；猫咪固定在底部。
- 响应式测试：160 宽三栏、104–159 双栏、<104 或低高度回退，中栏不被压缩到不可读宽度。
- 猫咪测试：82×46、左右对称、右耳无额外尖点、仅一个鼻点、无彩色 token、六种眼形可区分。
- 动画测试：眨眼、视线、半阖、睁大、弯眼和垂眼；关闭动画后同一状态帧不随时间变化；隐藏/销毁不排程。
- 原生渲染：检查字符帧与 color spans，尤其检查浅灰外圈不会吞掉瞳孔、外轮廓不会消失在背景中。
- 最终跑 TUI build + ESLint + 全量测试、分层/OpenTUI 探针和四包测试；真实终端观感与不同终端字形支持单独标注，不能由 headless 结果代替。

## 7. 留给实现者的决定

实现者可以决定辅助函数命名、面板行预算的具体计算、光栅字符映射表和测试文件组织，但必须保持上述视觉、状态、灰阶、响应式和兼容性约束。任何把 82×46 改成更低分辨率、把猫咪改成图片、或恢复文字标签的决定都需要重新确认。
