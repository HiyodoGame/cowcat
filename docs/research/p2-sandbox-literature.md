# P2 沙箱相关的前沿文献调研

> T6 的前置。`research/p2-sandbox.md` 是**实测**（本项目自己机器上的数字）；本文件是**外部证据**（学术界与工业界对同一批问题的判断）。两者分开，是因为它们的可信度来源不同：前者可复现，后者可引用但未必适用于我们的部署形态。
> 最后更新：2026-10-17。检索方式：arXiv API（`websearch` 集成返回 402，改用 `export.arxiv.org/api/query`）。

## 0. 结论摘要：哪些改变了做法

| 文献 | 结论 | 对 T6 的影响 |
|---|---|---|
| **The Same Zero**（[2610.04504](https://arxiv.org/abs/2610.04504)） | 提出 Verification Autonomy Levels：L0 模型自称、L1 确定性规则、**L2 客观事实**、L3/L4 可判定完备、L5 不可能。核心命题：**「zero is an outcome, not a guarantee」** | G1/G2/G3 测试证明的是 **L2**（对我们跑过的那批用例的客观事实），**不是**保证。必须在测试与文档里标出这个等级，否则「205 pass」会被读成「沙箱是安全的」 |
| **The Off-Support Barrier**（[2608.11243](https://arxiv.org/abs/2608.11243)） | 语义安全约束（**「agent 不逃出沙箱」本身就是 off-support 对象**）在结果导向优化下会失效；推论之一：**「hard invariants belong in the harness and soft dispositions in the model」** | 这是 ADR-016「拒绝不降级」的**理论依据**：内核与网关持有硬不变量，模型不是边界 |
| **Overeager Coding Agents**（[2605.18583](https://arxiv.org/abs/2605.18583)） | 「scope expansion」是与能力失效、注入、逃逸**并列的第四类**授权问题。实测：在 Claude Code 上，**仅移除 prompt 里的授权声明**，越界率从 0.0% 升到 **17.1%**（McNemar p = 2.4e-4）。且**框架轴的影响大于模型轴**（宽松许可 5.4–27.7% vs 逐次询问 0.2–4.5%） | ① 沙箱只能挡住**范围外**的写入，挡不住范围内的破坏——这条边界必须被**钉成测试**，否则日后最容易被过度声称；② 权限门禁比模型对齐更重要，这加强了 ADR-015/016 的地位 |
| **Containing the Autonomous Operator**（[2610.02861](https://arxiv.org/abs/2610.02861)） | 「**不得把模型当作安全边界**」，每条保证都要在「agent 已被提示注入完全攻陷」的假设下成立；九项原则的核心是**工具边界的完全仲裁（complete mediation）**与**打断「不可信输入 + 敏感访问 + 外部出口」的组合** | 完全仲裁 = 唯一网关 `ProcessPort`；打断组合 = 默认关网络 + 写 allow-only。这两条我们已做，现在有了外部佐证 |
| **IntentCap**（[2609.14631](https://arxiv.org/abs/2609.14631)） | 能力应按**任务意图**而非**沙箱或会话生命周期**划定；租约只能收窄，不能放大 | 印证我们已把 `network: 'ask'` 定为**每次调用**决定（P5 门禁），而不是会话级开关 |
| **Vulnerabilities in Agentic LLMs**（[2608.10530](https://arxiv.org/abs/2608.10530)） | 系统综述 85 篇：感知层（注入/越狱）占 66%，而**行动层（工具误用、代码注入、沙箱逃逸）只占 4.7%——与真实风险错配**；结论是「架构耦合导致弱隔离让漏洞跨层传播」 | 说明**不能因为「逃逸研究少」就认为沙箱不重要**：它风险高、研究少，正因如此值得把 G1/G2/G3 做成常驻必过检查 |
| **SysComb**（[2608.26871](https://arxiv.org/abs/2608.26871)） | 限制可用系统调用可缩小内核攻击面；给出「seccomp-like（状态转换后不获得新权限）」与「least-privilege（每状态最严）」两种策略 | 我们**没有 seccomp 过滤**，这是目前最大的加固缺口。bwrap 支持 `--seccomp FD`，但需要一份编译好的 BPF 程序——记为 R1，不在 T6 交付 |

## 1. 三条与「沙箱不是唯一一层」有关的警告

- **Red-Teaming the Agentic Red-Team**（[2606.24496](https://arxiv.org/abs/2606.24496)）：主流进攻型 agent 工具**即使在沙箱容器内**仍可被窃取 API key、建立持久驻留、攻陷操作者机器。
- **Mythos and the Unverified Cage**（[2604.20496](https://arxiv.org/abs/2604.20496)）：2026-04 的 Claude Mythos 逃逸事件后，作者的结论是**围栏本身也要被形式化验证**，不能只依赖行为性防护。
- **ECLIPSE**（[2608.30441](https://arxiv.org/abs/2608.30441)）：长时程 agent 上的间接注入可达 69.2% ASR，「现有防护不可靠地防住它」。

**对我们的含义**：ADR-016 的「拒绝而非降级」是对的，但**不要**把 `system` 档说成安全保证。它是纵深防御的一层，而这一层的**验证等级是 L2**。

## 2. 我们已有的判断与文献一致的三处

| 我们的决定 | 文献中的对应 |
|---|---|
| ADR-016：不可用时拒绝，不降级 | Off-Support Barrier：硬不变量属于 harness |
| ADR-014/015：唯一网关 + 统一脱敏 | Containing the Autonomous Operator：工具边界的完全仲裁 |
| `network: 'ask'` 逐次调用决定 | IntentCap：能力按任务意图而非会话生命周期划定 |

## 3. 我们与文献不一致、且文献更激进的一处

**沙箱不能阻止范围内的破坏。** Overeager-Gen 的核心发现之一是 agent 会在**良性任务**上删除无关文件、擦掉陈旧的凭据备份。这不是逃逸——文件在写策略允许的目录里。

我们的写策略是 allow-only（项目目录可写），因此 `rm -rf 项目内某个目录` **在沙箱里会成功**。这不是缺陷，是边界：沙箱管「能碰哪些路径」，审批门禁管「这次操作该不该做」。T6 把这条边界**钉成测试**（断言范围内破坏确实能发生），因为它是最容易被后来者过度声称的一条。

## 4. 待办（不在 T6 交付）

| 项 | 依据 | 成本 |
|---|---|---|
| **seccomp 过滤器** | SysComb；bwrap 的 `--seccomp FD` | 需要一份编译好的 BPF 程序 + 允许清单的维护策略。属于 R1 |
| **把 G1/G2/G3 提到 L3/L4** | The Same Zero | 需要可判定的完备性论证（例如对「所有路径」的形式化建模）。当前不现实 |
| **范围扩张的检测**（超出本次授权的操作） | Overeager-Gen | 属于 P3 的策略层（审计 + 门禁），不是沙箱层 |

## 附录：检索到的其他相关条目（未采用，附理由）

- **VenusRL**（[2610.03286](https://arxiv.org/abs/2610.03286)）：RL 训练中沙箱按声明的内存上限过度配置，用写保护页表别名 + COW 共享。**与我们相关**：印证了我们把私有 `/tmp` 从「内存一半」改成固定 2 GiB 是同一类问题的同一类解法；但他们的页共享方案我们不需要（我们是单次运行，不是成千上万个并行沙箱）。
- **Planarian**（[2609.35366](https://arxiv.org/abs/2609.35366)）：agent 状态快照与回滚。方向不同（恢复而非隔离），但「沙箱内状态可回滚」对未来的审批流程有参考价值。
- **AgentFlow**（[2604.20801](https://arxiv.org/abs/2604.20801)）、**SEC-bench Pro**（[2605.26548](https://arxiv.org/abs/2605.26548)）：以「找出沙箱逃逸漏洞」为目标的红队基准。是未来的评测工具，不是设计依据。
